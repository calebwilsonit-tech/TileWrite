# Known issues

- **Electron binary download is flaky on this machine (2026-10-16).** `node node_modules/electron/install.js` stalled twice on the GitHub release asset. Workaround used: `curl.exe -C -` with retries, verify SHA256 against `node_modules/electron/checksums.json`, unzip into `node_modules/electron/dist`, write `path.txt` containing `electron.exe`. Not a repo bug; document in `docs/BUILDING.md` if the user hits it.
- npm 11 blocks dependency install scripts by default; `esbuild` and `electron-winstaller` are approved in the root `package.json` `allowScripts`.
- CI workflow has never run (no remote repository yet).
- `dist:win` (editor installer) is wired up but untested; tracked under M12.
- `npm audit` reports a moderate issue (sprintf-js DoS, via `electron-builder` -> `app-builder-lib` -> `@electron/get` -> `global-agent` -> `roarr`). It is in the build tooling only and is not shipped in the editor or exported games. Revisit when `electron-builder` updates (M12).
- M3 deferred (listed in PROGRESS.md): hot reload during play, separate game window, Decoration/Walls/Lights layers, autotiling rules, per-height collision painting, bypass/soft-lock validators (M9), asset import (M4).
- The "Explain" button in the Problems panel is disabled until the Claude assistant exists (M11).
- Dock panels can be closed with their X; use Commands -> Reset panel layout to bring them back.

- M5 deferred: prefab children are not shown/edited individually in the editor; wires only combine with OR (use a Logic Gate for anything else); no visual state machine editor for enemy/boss behaviour (M7); echo/light/sentence-stone parts are M6; Health/Damage/Patrol/Chase/Vision/Boss are M7; inventory/NPC/Checkpoint/Portal are M8.
- Wire-tool and event-sheet UI are covered by one e2e plus unit tests, not by exhaustive interaction tests.
- M6 deferred: lights do not tint tiles (only a faint additive glow); region darkness has hard edges at the region border; shadows ignore decks/slopes; no edit-mode lighting preview (only in Play); sentence stones expose only the first four words as wire signals; no lantern fuel or light resource bar (M7/M8); echo/light/word objects have only procedural (box) art.- M7 deferred: no visual state-machine editor for enemy/boss behaviour (guards are configured, not drawn); enemies only use contact damage (no ranged attacks or projectile AI yet, though Projectile exists); hearing ignores walls; pathfinding is cell-based (guards walk centre to centre around obstacles) and does not avoid other guards; no light/resource bar or lantern fuel; the quill and dodge have no art or animation of their own (a blink and a pale swing shape); behaviour trees are not offered.
- M8 deferred: dialogues are edited as a list of steps, not a drawn node graph; the cutscene editor is a step list, not a visual timeline with tracks; no audio engine, so volume settings are stored but nothing plays yet (sound events are emitted as 'sound'); no video settings, minigames, cosmetic skins, hit-stop, or a localization string table; screen shake only comes from cutscenes; the world map is the Travel list (no drawn map); fast travel only goes to lit lanterns; saves of the editor's Play live in the project's saves/ folder (add it to version control ignores); other scenes load from their saved files while the open scene uses unsaved edits; in-game menus are keyboard/mouse/gamepad but menus themselves cannot be rebound.
- M9 deferred: the bypass check ignores dynamic helpers (it treats crates as removable and ignores echoes, bold-text walls and growing objects when deciding what blocks); jumping onto or over solid objects (a 1.6-high gate against a 1.7-high jump) is not modelled; soft-lock analysis covers crate puzzles only (not one-way drops, pits, or echo timing); the echo solver is a fixed recipe (one echo per plate), not a search; the playbot does not fight (enemies are ignored unless in the way) and does not use items; playthroughs record buttons only (not mouse clicks on the dialogue choices); debug overlays do not show AI state names; no per-frame draw-call count (Pixi does not expose one cheaply); 'Explain' and 'Fix with Claude' stay disabled until M11.

- M10 deferred / limits: scripts are not sandboxed (see D015); breakpoints pause after the step in which they were reached, not mid-function, and cannot step line by line (Step advances one frame); only the open script gets Monaco's live type diagnostics (other scripts' compile errors still appear in the Code window's Problems list, but not in the scene Problems panel, which only reports objects using a script that no longer exists); there is no "Go to" from the scene Problems panel into a script line; watch expressions read values but cannot show the call stack or locals; scripts cannot import other scripts or packages; exported games do not yet compile scripts (M12 reuses the same transpile path); Monaco's TypeScript worker makes the editor bundle large (~7 MB, loaded only when the Code window opens); the watch list is kept in `localStorage`; "Explain" / "Fix with Claude" stay disabled until M11.
- Test flakiness (watch): `e2e/m7-combat.spec.ts` once failed on `boss.active` when all 17 specs ran in parallel on a busy machine (the next two full runs were clean). The spec drives the real-time runner between pauses; if it recurs, move it to a fully step-driven helper like `m10-code.spec.ts`.

- M11 limits: **never run against the live API in this environment** (no key): behaviour is verified against a mock server that speaks the streaming Messages protocol and by unit tests; run `npm run test:live` with your key to check the real thing (the refusal-fallback beta and thinking/effort parameters are the parts most worth watching). Claude cannot see the game running (only a screenshot of the editor viewport), cannot edit story data (items, conversations, cutscenes) or prefabs yet, cannot add regions, and cannot change the project file; event rows can be replaced as a whole sheet only (no row-level edit); nested sub-events are limited to two levels in the tool schema. Proposals are shown one at a time. The "Undo this" button only works while nothing else has been changed since (otherwise use Ctrl+Z). There is no conversation history across restarts. Costs are estimates from list prices. The Claude tab shares a narrow column with the Inspector.

- M12 limits: **the NSIS installer (`Tilewright-<version>-win.exe`) has not been built here**: electron-builder's download of its NSIS and signing helpers from GitHub stalled on this machine (the same flaky-download problem as the Electron binary). What was verified: `electron-builder --win dir/zip` with the local Electron (packaged editor, `release/win-unpacked`, a 160 MB zip), and exporting a game from that packaged editor and running it (`e2e/packaged-export.spec.ts`). The CI `windows-build` job builds the real installer and runs that spec; it has never run (no remote repository). Exported games keep the generic Electron file icon and file properties on the .exe (no resource editing without the signing helpers); the window and taskbar icon come from the chosen PNG. No code signing, so SmartScreen warns. Export works only for the platform the editor runs on (Windows and Linux; the Linux path is untested here) and macOS is not implemented. A game and its zip are 250-300 MB because each carries a full Electron runtime. Exported games have no audio (the engine has none yet) and no in-game language settings. The saved game settings live in the browser storage of the game window (`localStorage`), saves in the game's own folder.
- The e2e run once filled the disk (535 leftover temp folders from earlier runs, 8 GB); `e2e/clean-temp.ts` now removes them before and after each run.
