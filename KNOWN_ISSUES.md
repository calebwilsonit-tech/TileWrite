# Known issues

- **Electron binary download is flaky on this machine (2026-10-16).** `node node_modules/electron/install.js` stalled twice on the GitHub release asset. Workaround used: `curl.exe -C -` with retries, verify SHA256 against `node_modules/electron/checksums.json`, unzip into `node_modules/electron/dist`, write `path.txt` containing `electron.exe`. Not a repo bug; document in `docs/BUILDING.md` if the user hits it.
- npm 11 blocks dependency install scripts by default; `esbuild` and `electron-winstaller` are approved in the root `package.json` `allowScripts`.
- CI workflow has never run (no remote repository yet).
- `dist:win` (editor installer) is wired up but untested; tracked under M12.
- `npm audit` reports a moderate issue (sprintf-js DoS, via `electron-builder` -> `app-builder-lib` -> `@electron/get` -> `global-agent` -> `roarr`). It is in the build tooling only and is not shipped in the editor or exported games. Revisit when `electron-builder` updates (M12).
- M3 deferred (listed in PROGRESS.md): hot reload during play, separate game window, Decoration/Walls/Lights layers, autotiling rules, per-height collision painting, bypass/soft-lock validators (M9), asset import (M4).
- The "Explain" button in the Problems panel is disabled until the Claude assistant exists (M11).
- Dock panels can be closed with their X; use Commands -> Reset panel layout to bring them back.

- M5 deferred: prefab children are not shown/edited individually in the editor; wires only combine with OR (use a Logic Gate for anything else); no visual state machine editor for enemy/boss behaviour (M7); echo/light/sentence-stone parts are M6; Health/Damage/Patrol/Chase/Vision/Boss are M7; inventory/NPC/Checkpoint/Portal are M8.
- Wire-tool and event-sheet UI are covered by one e2e plus unit tests, not by exhaustive interaction tests.
- M6 deferred: lights do not tint tiles (only a faint additive glow); region darkness has hard edges at the region border; shadows ignore decks/slopes; no edit-mode lighting preview (only in Play); sentence stones expose only the first four words as wire signals; no lantern fuel or light resource bar (M7/M8); echo/light/word objects have only procedural (box) art.- M7 deferred: no visual state-machine editor for enemy/boss behaviour (guards are configured, not drawn); enemies only use contact damage (no ranged attacks or projectile AI yet, though Projectile exists); hearing ignores walls; pathfinding is cell-based (guards walk centre to centre around obstacles) and does not avoid other guards; no light/resource bar or lantern fuel; the quill and dodge have no art or animation of their own (a blink and a pale swing shape); behaviour trees are not offered.
- M8 deferred: dialogues and cutscenes are edited as lists (a graph and a timeline view were added later); (sound and hit-stop were added in M14); no minigames or cosmetic skins (video settings and localization came later); the world map is the Travel list (no drawn map); fast travel only goes to lit lanterns; saves of the editor's Play live in the project's saves/ folder (add it to version control ignores); other scenes load from their saved files while the open scene uses unsaved edits; in-game menus are keyboard/mouse/gamepad but menus themselves cannot be rebound.
- M9 deferred: the bypass check ignores dynamic helpers (it treats crates as removable and ignores echoes, bold-text walls and growing objects when deciding what blocks); jumping onto or over solid objects (a 1.6-high gate against a 1.7-high jump) is not modelled; soft-lock analysis covers crate puzzles only (not one-way drops, pits, or echo timing); the echo solver is a fixed recipe (one echo per plate), not a search; the playbot does not fight (enemies are ignored unless in the way) and does not use items; playthroughs record buttons only (not mouse clicks on the dialogue choices); debug overlays do not show AI state names; no per-frame draw-call count (Pixi does not expose one cheaply); 'Explain' and 'Fix with Claude' stay disabled until M11.

- M10 deferred / limits: scripts are not sandboxed (see D015); breakpoints pause after the step in which they were reached, not mid-function, and cannot step line by line (Step advances one frame); only the open script gets Monaco's live type diagnostics (other scripts' compile errors still appear in the Code window's Problems list, but not in the scene Problems panel, which only reports objects using a script that no longer exists); there is no "Go to" from the scene Problems panel into a script line; watch expressions read values but cannot show the call stack or locals; scripts cannot import other scripts or packages; exported games do not yet compile scripts (M12 reuses the same transpile path); Monaco's TypeScript worker makes the editor bundle large (~7 MB, loaded only when the Code window opens); the watch list is kept in `localStorage`; "Explain" / "Fix with Claude" stay disabled until M11.
- Test flakiness (watch): `e2e/m7-combat.spec.ts` once failed on `boss.active` when all 17 specs ran in parallel on a busy machine (the next two full runs were clean). The spec drives the real-time runner between pauses; if it recurs, move it to a fully step-driven helper like `m10-code.spec.ts`.

- M11 limits: **never run against the live API in this environment** (no key): behaviour is verified against a mock server that speaks the streaming Messages protocol and by unit tests; run `npm run test:live` with your key to check the real thing (the refusal-fallback beta and thinking/effort parameters are the parts most worth watching). Claude cannot see the game running (only a screenshot of the editor viewport), cannot edit story data (items, conversations, cutscenes) or prefabs yet, cannot add regions, and cannot change the project file; event rows can be replaced as a whole sheet only (no row-level edit); nested sub-events are limited to two levels in the tool schema. Proposals are shown one at a time. The "Undo this" button only works while nothing else has been changed since (otherwise use Ctrl+Z). There is no conversation history across restarts. Costs are estimates from list prices. The Claude tab shares a narrow column with the Inspector.

- M12 limits: **the NSIS installer (`Tilewright-<version>-win.exe`) has not been built here**: electron-builder's download of its NSIS and signing helpers from GitHub stalled on this machine (the same flaky-download problem as the Electron binary). What was verified: `electron-builder --win dir/zip` with the local Electron (packaged editor, `release/win-unpacked`, a 160 MB zip), and exporting a game from that packaged editor and running it (`e2e/packaged-export.spec.ts`). The CI `windows-build` job builds the real installer and runs that spec; it has never run (no remote repository). Exported games keep the generic Electron file icon and file properties on the .exe (no resource editing without the signing helpers); the window and taskbar icon come from the chosen PNG. No code signing, so SmartScreen warns. Export works only for the platform the editor runs on (Windows and Linux; the Linux path is untested here) and macOS is not implemented. A game and its zip are 250-300 MB because each carries a full Electron runtime. Exported games play sound (M14) but have no in-game language settings. The saved game settings live in the browser storage of the game window (`localStorage`), saves in the game's own folder.
- The e2e run once filled the disk (535 leftover temp folders from earlier runs, 8 GB); `e2e/clean-temp.ts` now removes them before and after each run.

- M13 limits: the acceptance slice is deliberately small (two scenes, placeholder box art, no audio, no music, no particles) and its geometry is chosen so that the bot and the checks can judge it (long straight walls with one-cell gaps, a dead-end crate corridor). The bot's walkthrough is a script (`e2e/slice-bot.ts`), not a generic "play any game" solver: it knows to talk, light lanterns, hold echo plates, solve crates, swap stones, fight and walk to the goal in that order for this game; the generic bits (`Bot.fight`, `Game` with scenes, `holdPlatesWithEchoes`, the crate solver) are reusable but there is no one-button "play the whole game" yet. The bypass check treats text blocks as always bridgeable (it cannot tell whether the stone is ever swapped to the right word). The crate checks assume the player has opened earlier gates. Mouse placement near tall walls can land on the wrong cell (the test corrects positions in the Inspector); the editor does not yet pick through walls.

- M14 limits (sound and effects, the sample): **nobody has listened to the sound**. The engine is tested against a pretend sound card (nodes, fades, voice cap, pitch drift), and a real WAV was added, decoded and picked up as a room's music inside the Electron window, but no test hears it and this machine's output was not checked by ear. There is no mixer UI, no sound grouping or random-pick lists, no 3D/positional sound, no ducking, no loop points (music loops end to end) and no live editing of a sound while the game runs (reload it by pressing Play again). Pitch variation is fixed at 5 percent. Hit-stop and shake follow one setting (Settings -> Screen shake and hit freeze), not two. Particles are small squares from seven presets; there is no particle editor and they are not drawn in the sprite studio. Hit-stop is applied by the game window, so single-stepping with the editor's Step button does not show it. The sample game is the box-art slice (see M13 limits) and is only regenerated by running the acceptance test with `TILEWRIGHT_SAMPLE_OUT`.
- Still owed since earlier milestones and not done: autotiling rules and the Decoration / Walls / Lights layers, hot reload while playing and a separate game window, vector drawing in the sprite studio, a visual state-machine editor, a dialogue graph canvas and a visual cutscene timeline, localization string tables, video settings, minigames, cosmetic skins, assistant tools for story data / prefabs / regions. These are in the spec but are bigger than polish; they are listed here so the final summary can say so honestly.

- Autotiling and layers limits: variants are chosen while editing and stored in the map (the game draws what each cell holds); changing the rules does nothing to scenes you do not open, so run **Save and apply to this scene** in each scene (the project check warns about tiles that no longer exist but not about stale looks). The 30-variant edge set is a rim and corner dots, not 47 blob-tile art; with real tile art the same rules choose sprites, but tiles are still procedural colours today and there is no tile art import. A cell's look depends on its eight neighbours and their heights only (not on objects, flags or decks); pits, water flags and slopes do not take part. Painting a variant by hand is not offered (variants are hidden from the palette); a tile with rules always snaps back to what the rules say. The Walls layer is "tiles marked as a wall" (brick by default; projects made earlier must tick it in the Autotiling dialog), not a second map layer; Decoration is "objects with the decoration tag", also not a separate layer of tiles. Layer visibility and locks are for editing and are not saved with the project. There is no lighting preview in the editor, only in Play.

- Localization and video limits: the original text is the key of every translation, so editing a line in the game makes its translations "no longer in the game" and the line shows untranslated until it is translated again (the dialog says how many; there are no string ids that survive a rewrite). Names of objects (guards, lanterns in the Travel list), puzzle text (sentence stones, text blocks) and text written by scripts are not translated. Text is one string per line: no plural forms, no gender, no right-to-left layout and no font switching, so languages that need other fonts depend on what fonts the player's computer has. The Language row cycles through languages (no list). Camera zoom is four steps; there is no resolution, vsync or windowed-borderless setting. Full screen can be switched from the pause menu and with F11; the two are not kept in step (the row shows the window's real state when the menu opens). Only the exported game can go full screen; Play in the editor never switches the editor's window.

- Dialogue graph and cutscene timeline limits: card positions are saved in the dialogue file (`x`, `y`) and only the graph reads them; the timeline is a view of the steps (order and "keep going"), so you cannot drag a block to a different time, only stretch a timed step; the lengths of speech, dialogue and walks are guesses; the timeline cannot show what happens inside a dialogue step; both views work with mouse only (the graph can be panned and zoomed with buttons, but cards cannot be moved or connected with the keyboard: use the form fields, which have a "Then go to" list). Undo for story edits does not exist (they save as you type), as before.

- Hot reload and game window limits: Apply edits loads the open scene again, so enemies, crates, gates and everything else that moved go back to their starting places and rows set to "only once" that already ran stay done (the player's place, items, flags, health and the row memory are kept); other scenes are not reloaded, and edits to a scene you are not standing in take effect when you travel there only if it is the open scene (travel loads scenes from files on disk). Terrain edits that put the player inside a wall are not corrected. Scripts reload as before; a script that changes its own state keeps nothing. "In a window" saves the open scene first (it runs from files, like an export), starts a fresh game each time (no state is carried over, and it does not follow your later edits: press the button again), shares the project's `saves` folder with the editor's own Play. It uses the editor's own window code, so it should work in the packaged editor too, but that was only checked from the built folder.
